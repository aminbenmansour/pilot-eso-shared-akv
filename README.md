# pilot-eso-shared-akv

Pilot configuration for implementing a shared Azure Keyvault with ESO through RBAC rules and role_assignment(s)

## Terraform module: `eso-app-identity`

Reusable module that gives an application access to its secrets in a shared Key
Vault: managed identity + federated credential + prefix-scoped role assignment +
the annotated ESO service account. See the
[module documentation](modules/eso-app-identity/README.md) for the full input and
output reference.

Consume it directly from this repository, no clone required:

```hcl
module "glitchtip_identity" {
  source = "git::https://github.com/aminbenmansour/pilot-eso-shared-akv.git//modules/eso-app-identity?ref=v1.0.0"

  app                 = "glitchtip"
  env                 = "dev"
  location            = azurerm_resource_group.this.location
  resource_group_name = azurerm_resource_group.this.name
  namespace           = "glitchtip"
  key_vault_id        = azurerm_key_vault.this.id

  oidc_issuer_url = data.azurerm_kubernetes_cluster.this.oidc_issuer_url
}
```

The `kubernetes` provider is not configured by the module. With AKS, either use
the local kubeconfig context:

```hcl
provider "kubernetes" {}
```

or configure it explicitly, for example with the cluster's kube config. The
repository is public, so no credentials are needed; private mirrors can follow
the authentication guidance in the module README.

The module requires the application namespace to exist and, for existing
clusters, that the previously hand-created service account is deleted or
imported.

## Kubernetes manifests

`kubernetes/manifests` contains only the `SecretStore` and `ExternalSecret`. The
service account is generated by Terraform, see above.
